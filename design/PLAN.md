# План внедрения редизайна

Каждый этап — отдельная ветка и коммит. Следующий начинается только после того, как предыдущий проверен на телефоне в светлой и тёмной теме.

## Как начать в Claude Code

1. Положи папку `design/` в корень репозитория `trener`.
2. Добавь в `CLAUDE.md` (создай, если его нет):

```md
## Дизайн
- Дизайн-система — design/README.md. Прочитай её перед любой правкой UI.
- Цвета, шрифты, отступы и радиусы — только через переменные из design/tokens.css. Никаких hex в CSS компонентов.
- Макеты — design/screens/*.html. Это референс по виду, а не код для копирования.
- Работаем по этапам из design/PLAN.md. Один этап — одна задача. Не забегай вперёд.
- Цвет не бывает единственным сигналом: у верно/ошибка всегда есть слово или ✓/✕.
```

3. Первый промпт:

> Прочитай design/README.md и design/PLAN.md. Сделай только этап 1. Перед правками покажи план изменений в index.html и cabinet.js, дождись моего «ок».

---

## Этап 1. Токены и шрифты

Только внешний вид, логика не трогается.

- Заменить блок `:root` и все `[data-theme=…]` в `index.html` на подключение `design/tokens.css`. Благодаря алиасам (`--bg`, `--accent`, `--muted`, `--r`) остальной CSS продолжит работать.
- Удалить темы `sepia` и `forest` и их кнопки-кружки. Оставить `paper` и `night`. Сохранённый выбор `sepia`/`forest` в localStorage должен превращаться в `paper`.
- `font-family` у `body` → `var(--font-sans)`. Заголовки (`.home h1`, `.land h1`, `.cab-h`, `.allhead h1`) и крупные числа (`.ring .lab b`, `.resbox b`, `.pstat b`) → `var(--font-display)`. Название «Маша Вайб» в шапке → `var(--font-display)`, 700.
- Везде, где стоит `color:#fff` на фоне `var(--accent)` (`.btn`, `.vdot`), поставить `var(--on-cobalt)`. Иначе в тёмной теме будет белый текст на светло-синем фоне.
- Радиусы: `.qn`, `.st-ok`, `.st-wait`, `.tbadge` → `var(--radius-cell)`; `.btn`, `.field`, `.tin`, `.tcard` → `var(--radius-md)`.

**Готово, когда:** все экраны открываются без ошибок в консоли; в обеих темах нет белого текста на светлом фоне; шрифты грузятся (во вкладке Network видно Unbounded и Onest).

## Этап 2. Клетки ответа и вердикт

Референсы: `screens/question.html`, `screens/questionnight.html`, компоненты AnswerCells и Verdict.

- Поле `.field` → клетки бланка. Под ними остаётся **один** настоящий `<input inputmode="numeric" autocomplete="off">`, визуально скрытый, но в фокусе. Клетки только отображают значение. Число клеток = длина правильного ответа, но не меньше 3 и не больше 6.
- Должны работать: вставка из буфера, Backspace, стрелки, мобильная цифровая клавиатура, Enter = «Проверить».
- Вердикт: «✓ Верно» / «✕ Ошибка»; «Почти» — если совпало больше половины цифр. При ошибке — «Правильный ответ: 135» шрифтом `--font-mono`.
- В разборе ключевой термин можно выделить классом `.mv-hl` (маркер), не больше одного на абзац.
- Встряска при ошибке уже есть — сохранить; при `prefers-reduced-motion` отключить.

**Готово, когда:** на iPhone и Android открывается цифровая клавиатура, вставка «135» заполняет три клетки, экранный диктор читает ответ как одно поле.

## Этап 3. Экран результата

Референс: `screens/result.html`.

- Крупно: «26 из 33» и изменение к прошлой работе по этому же ДЗ или разделу.
- Три плитки: верно / ошибок / процент.
- Блок «Где ошибки»: группировка ошибок по теме вопроса. Если у вопросов нет тем — **сначала этап 5a**, до тех пор блок скрыт.
- Кнопки: «Исправить N ошибок» (главная) → прогон только по ошибкам; «Отправить работу учителю» (ghost) — существующая логика.

**Перед этим этапом:** добавить логирование активности (таблица `activity`: `student_id`, `date`, `answers_count`). Без неё не посчитать ни серию дней, ни удержание.

## Этап 4. Серия дней

- Серия = число дней подряд, когда решено хотя бы одно задание (по часовому поясу Москвы).
- Одна «заморозка» в неделю: пропущенный день не обнуляет серию. Без этого потеря 20-дневной серии демотивирует сильнее, чем серия мотивировала.
- Плашка серии (`.mv-streak`) — в шапке и на экране результата. Жёлтый маркер — не больше одного пятна на экран.

## Этап 5. Разделы кодификатора

**5a — данные.** Каждому вопросу проставить тег раздела: `chelovek`, `ekonomika`, `socialnye`, `politika`, `pravo` (и при желании подтему). Это ручная или полуавтоматическая разметка — самая дорогая часть всего редизайна.

**5b — ученик.** Референсы `screens/progress.html`, `screens/home.html`: шкалы по разделам (последние 30 ответов раздела), ниже 50% — «слабое место», кнопка «Тренировать».

**5c — учитель.** Референс `screens/teacher.html`: вкладка «Обзор группы» — тепловая карта ученики × разделы, очередь «На проверке», «Требуют внимания» (5+ дней без заданий или −10% за 3 работы).

## Не делать без решения

- «Сейчас около 64 баллов» на главной. Перевод процента в тестовые баллы — оценка. Если она ошибается, ученик перестанет доверять экрану. Либо честная подпись «примерно, по последним 5 работам», либо только проценты.

## Метрика

Главная метрика — доля учеников, которые решали хотя бы 3 дня за неделю. Замерить неделю **до** этапа 2 и сравнивать после каждого этапа.
