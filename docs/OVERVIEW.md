# Обзор проекта «ЕГЭ с Машей Вайб» — для нового чата

Прочитай целиком перед работой: здесь всё, что обычно приходится объяснять заново. Состояние на 26.09.2026.

## Что это

Тренажёр ЕГЭ по обществознанию для ~100 учеников репетитора Маши (сайт **https://mashavibe.ru**, репозиторий `kupikrutcher/trener`, ветка `main`).
- **Ученик**: уроки (видео, описание, файлы, ДЗ с дедлайном) → решает ДЗ → отправляет учителю → видит баллы, прогресс, разбор. Тесты ученику видны **только через уроки**; есть банк заданий части 1 для тренировки.
- **Учитель** (Маша, аккаунт `irina_trushina`): ведёт уроки, проверяет часть 2 (баллы, комментарии, файлы), заводит учеников (логины/пароли выдаёт сам, ученики не регистрируются и не меняют имя), собирает ДЗ из банка.
- Общаемся с владельцем **по-русски, просто и по делу**. Правки UI — по `design/README.md` (голос: к ученику на «ты», без «!», верно/ошибка никогда не только цветом — всегда слово или ✓/✕).

## Как всё выкладывается

**Сайт** — статика в Yandex Object Storage (бакет `mashavibe.ru`, DNS в Cloudflare «DNS only» — не трогать). Любой пуш в `main`, меняющий `index.html`, `cabinet.js`, `tests.json`, `bank.json`, `design/tokens.css`, `design/styles/**`, `img/**`, `backend/publish-site.js`/`s3.js`, запускает GitHub Actions → `backend/publish-site.js` грузит файлы в бакет (текст — gzip, `Cache-Control: no-cache`). Список файлов — `FILES` в `publish-site.js`; **новый файл сайта надо дописать туда** (кроме `img/tasks/*` — они подхватываются сами).
Проверить публикацию: `gh run list -R kupikrutcher/trener --workflow publish-site.yml --limit 1`. `kupikrutcher.github.io/trener` — запасное зеркало (там работают только ссылки с главной).

**Сервер** — Yandex Cloud Function `trener-api` (`https://functions.yandexcloud.net/d4epjak23r01meequ6fs`, прописан в `cabinet.js` → `API_URL`) + YDB serverless `trener-db` + бакет файлов уроков `trener-files-<folder>`.
- Разворачивается **из отдельной папки `~/Desktop/trener-backend`** (не git!): туда копируют изменённые `backend/*.js` из репозитория, затем `./deploy.sh`. Там же `.secrets` — **никогда не читать и не выводить**. deploy.sh в конце печатает SETUP_CODE — при запуске фильтруй: `./deploy.sh 2>&1 | grep -v -i "SETUP_CODE\|secret"`.
- deploy.sh сам создаёт недостающие таблицы/колонки по `TABLES` (новая колонка → просто добавь в `TABLES`, `*_COLS`, `putX`, `xRow`).
- Нужен доступ к Яндексу: у владельца часто включён VPN, тогда `functions.yandexcloud.net`/`mashavibe.ru` обрываются. Проверка: `curl -s -o /dev/null -w "%{http_code}" https://functions.yandexcloud.net/` (204 — можно). Если VPN мешает — проси владельца.
- **Порядок всегда: сначала сервер (deploy.sh), потом пуш сайта**, иначе сайт зовёт несуществующие действия.

## Как проверять локально

- `cd backend && npm test` — тесты сервера (сейчас 16+, все должны проходить).
- `node backend/dev-server.js --demo` → http://localhost:8770 (`PORT=…` для другого порта). Сайт + API + файлы в памяти; демо-уроки в 2 блоках, работы ученицы. Логины: ученик `demo`/`demo1234`, учитель `masha`/`teacherpass`. Внизу панель «Демо» (переходы по экранам).
- Войти без ввода пароля (удобно для браузерных проверок): `node -e "console.log(require('./backend/app').signToken('dev-secret',{login:'masha'}))"` → положить в `localStorage.tr_token`. Секрет `dev-secret` — только у локального сервера.
- Проверяй телефонную ширину (375px) и обе темы (`setTheme('paper'|'night')`), консоль без ошибок. После правок сервера перезапускай dev-server (он держит app.js в памяти).
- Сайт на неизвестный путь отдаёт `index.html` (и бакет — с кодом 404, это нормально).

## Фронтенд: как устроено

Один документ, экраны рисуются в `#app` (`cabShow(html)` / `app.innerHTML`). Два скрипта, общие глобальные переменные (без модулей).

**Адреса экранов** (`index.html`: `setUrl`, `route`, `dispatch`; `cabinet.js`: `cabRoute`). Каждый экран в начале зовёт `setUrl('…')`; «назад/вперёд» и обновление работают; без входа — сначала логин, потом туда, куда шли. `<base href="/">` — все пути к файлам относительные.

| Адрес | Экран | Кто |
|---|---|---|
| `/` | главная с фото (только при входе на сайт) | все |
| `/login` | вход | гость |
| `/lessons`, `/lessons/<id>` | уроки по блокам / урок | ученик, учитель |
| `/lessons/new`, `/lessons/<id>/edit` | редактор урока | учитель |
| `/schedule`, `/schedule/hw` | план курса (`COURSE_PLAN`, сентябрь 2026–май 2027, есть календарь) / уроки и дедлайны | все вошедшие |
| `/bank` | банк заданий частей 1 и 2 (фильтры блок/тема/номер, «Решать подборку»; учитель — сборка ДЗ) | все вошедшие |
| `/files` | материалы всех уроков | все вошедшие |
| `/course/check`, `/course/lessons`, `/course/tests` | курс учителя: Проверка / Уроки («Создать урок») / Готовые ДЗ (папки) | учитель |
| `/cabinet` | ученик: профиль, прогресс, мои работы; учитель: ученики, пароль, выход | вошедшие |
| `/works/<id>` | работа: разбор (ученик) / проверка части 2 (учитель) | вошедшие |
| `/tests/<id>` | решение теста; ученику — только если тест есть в его уроке | вошедшие |

**Левая панель** (`.side`): Проверка (учитель) / Уроки / Расписание / Банк заданий / Полезные файлы; на телефоне — бургер. Название «ЕГЭ с Машей Вайб» ведёт к урокам. Тема — одна кнопка (полумесяц ↔ солнце).

**Решение теста** (`index.html`): `openTest(id)` → `begin()` → `render()`.
- Часть 1: одно поле ввода цифр, «Дальше» (`saveP1`) сохраняет **молча** — верно/ошибка ученик видит только после завершения ДЗ (экран результата, «Все задания с ответами» с «Твой ответ ✓/✕»). Номера вопросов сверху — просто «отвечено».
- Проверка ответа `isRight`: задание на соответствие (`qType` ищет фразу **«Установите соответствие»**) — строгий порядок цифр; остальное — набор цифр в любом порядке.
- Часть 2: текстовое поле, черновик в `localStorage` (`ansKey` — по **названию** ДЗ), проверяет учитель.
- Правильные ответы и пояснения ученику открываются **только после отправки работы** (`answersLocked` в cabinet.js; учителю и в разборе — всегда).
- После отправки ученик может решать заново **только часть 1** (`p1OnlyFor` → `testBank`), повтор учителю не уходит.
- Отправка — `sendWork` (действие `submit`): часть 1 (ответы, верно/нет, баллы), часть 2 (тексты). Экран результата: плитки, «Где ошибки», «Исправить N ошибок» (`startMistakes`), изменение к прошлой попытке.
- Картинки к заданиям: поле `img` (+ `alt`) у задания, встаёт на место `[рисунок]` в тексте (`qImg` внутри `fmtQ`/`fmtLong`), по нажатию открывается в полный размер.

**Уроки** (`cabinet.js`): поля `title, block (номер блока), descr (описание), video (Kinescope/Rutube/VK/YouTube → embed, функция videoEmbed есть и в app.js, и в cabinet.js — менять обе), test_name (ДЗ по НАЗВАНИЮ теста), deadline, files, published`. Ученику — «Блок N» раскрывающимися группами, внутри от первого урока к последнему; в карточке «15 тестовых · 4 развёрнутых» (`hwCount`), без ДЗ — пусто. Дедлайны — отдельным боксом.

**Сеть**: `api(action, data)` — POST `text/plain` с `{action, token, …}`; при ответе 429 (облако занято) до 4 повторов с паузами. Токен входа в `localStorage.tr_token` — **бессрочный** (отключается только удалением пользователя).

`localStorage`: `tr_token`, `tr_theme`, `tr_open` (раскрытые папки ДЗ), `tr_lblocks` (раскрытые блоки уроков), `tr_bankf` (фильтры банка), `tr_ans_<название ДЗ>_<i>` (черновики части 2), `tr_ans_bank_<хеш текста>` (черновики части 2 из банка).

## Данные ДЗ (`tests.json`) и как добавлять новое ДЗ

`tests.json` — массив `{name, questions:[…]}`, сериализация `json.dumps(t, ensure_ascii=False, separators=(',',':'))` (держи этот формат — чистый diff).
- Часть 1: `{n, text, answer, explanation}` — `answer` только цифры; для соответствия — строго по буквам А–Д.
- Часть 2: `{part:2, n, pts, text, answer, explanation}` — `answer` = «Образец ответа» (ученик видит после отправки), `explanation` = критерии; в большинстве старых ДЗ оба пустые.
- Картинка: `img: "img/tasks/…png"`, `alt`, в тексте метка `[рисунок]`.
- Текст: варианты с новой строки `1) …` (или в строку `1) …; 2) …`), для соответствия заголовки столбцов прописными, `А) …`, в конце «Запишите в таблицу выбранные цифры под соответствующими буквами.» Текст к 17–20 кладут в начало задания 17 (как в «Налогах», «Пробнике №1»).
- Баллы части 2 по номеру ЕГЭ: 17–2, 18–2, 19–3, 20–3, 21–3, 22–4, 23–3, 24–4, 25–6.
- Папки «Готовых ДЗ» — `SECTIONS` в `index.html` (`[название папки, [названия ДЗ]]`); не попавшие — в «Другое». Сейчас: Нарешка, Человек и общество, Экономика, Социальные отношения, Политика, Право, **1 блок** (Урок 2, Урок 4, Урок 5), **Пробники** (Пробник №1).
- ДЗ, собранные учителем из банка, хранятся на сервере (таблица `hws`, действия `hw_*`), у них `id` = `c<id>`, свои папки; у ДЗ из файла `id` = `b<индекс>` (меняется при удалении — не храни его).
- **Урок ссылается на ДЗ по названию**: переименование/удаление ДЗ оставляет такие уроки без ДЗ — предупреждай владельца.
- Чек-лист нового ДЗ: ответы из ключа (если в выгрузке Google-формы есть «Правильный ответ» — берём его, иначе «ответ ученика»); проверь скриптом, что цифры ответа есть среди вариантов и у соответствия цифр столько же, сколько букв; сверь «Да/верно» в пояснениях с ответом; пояснения — из источника, если нет — ищем в `bank.json`/других ДЗ (только дословно совпавшие варианты с тем же Да/Нет), остальное пишем сами и говорим владельцу, какие чьи; добавь в `SECTIONS`; проверь локально `isRight` по ключу.

## Сервер

`handle()` в `app.js`: сначала `login`, `setup` (первый учитель по SETUP_CODE), дальше только с токеном. Токен = `base64url({l: login, c: created_at}).HMAC(SECRET)`; сервер берёт пользователя из базы и сверяет `created_at` (ключ удалённого ученика не подходит к новому аккаунту с тем же логином). Роль — из базы, `onlyTeacher()` на всех учительских действиях.

Действия: `me, set_avatar, change_password, submit, my_subs, sub_get, grade, subs_list, todo_count, students_list, students_create, student_reset, student_delete, lessons_list, lesson_get, lesson_save, lesson_delete, hw_list, hw_save, hw_delete, file_upload_url`.
Таблицы YDB: `users, avatars, subs (сводка работы), sub_body (ответы, оценки, файлы проверки), lessons, hws`.
Файлы уроков/проверки — в бакете через подписанные ссылки (`file_upload_url`, скачивание — `downloadUrl`).
Нагрузка: функция 256 МБ, 1 запрос на копию, квота облака — 10 одновременных вызовов; при 100–300 одновременных запросах с повтором на сайте всё проходит, ожидание в пике 1–4 с (замер 26.09). Параметр `--concurrency 8` пробовали — выигрыша нет.

## Известные особенности и долги

- **На 26.09 серверная часть «ДЗ из банка» (`hw_list/hw_save/hw_delete`, таблица `hws`) есть в репозитории, но не развёрнута** — в `~/Desktop/trener-backend` старые `app.js`, `db-ydb.js`, `db-memory.js`. Сайт это переживает (`hw_list` падает тихо), но сохранить ДЗ из банка нельзя, пока не скопировать эти файлы и не запустить deploy.sh. Сверяй: `cmp backend/app.js ~/Desktop/trener-backend/app.js`.
- **Ответы и пояснения всех ДЗ и банка лежат в браузере** (`tests.json`, `bank.json`) — подкованный ученик может их найти. Лечится только переносом проверки части 1 на сервер (не сделано).
- В старых ДЗ на месте графиков/диаграмм стоит `[рисунок]` без картинки (нет исходников).
- Смена пароля не выкидывает уже вошедшие устройства; отключает только удаление ученика.
- Статика бакета на «глубоких» адресах отвечает 404 с телом `index.html` — это ожидаемо.
- Рабочие копии на машине: `~/Desktop/trener` (main, там может работать параллельная сессия — не трогай чужие незакоммиченные правки), `~/Desktop/trener-urls` (ветка `urls`), `~/Desktop/trener-air` (`air-v2`). Работай в отдельной worktree от свежего `origin/main` и пушь `git push origin <ветка>:main`, предварительно `git fetch && git rebase origin/main`.

## Как работать (договорённости с владельцем)

1. Коротко скажи план → сделай → проверь локально (скриншот, телефон, обе темы) → коммит **с понятным сообщением на русском** → пуш в `main` → проверь, что GitHub Actions прошёл.
2. Правил сервер — прогони тесты, скопируй изменённые файлы в `~/Desktop/trener-backend/`, разверни (сам, если Яндекс доступен, или попроси владельца), и только потом пушь сайт.
3. Секреты не вводить и не просить; если нужен секрет в GitHub — дай владельцу команду `gh secret set`.
4. Сомнительные данные (опечатки в источнике, противоречие ключа и пояснения) — исправляй очевидное и сообщай, спорное — спрашивай.
